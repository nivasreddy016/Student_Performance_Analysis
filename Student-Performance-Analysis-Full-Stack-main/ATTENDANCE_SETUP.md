# Students and Attendance additions

## What changed
- Added Students directory navigation with branch, section, semester and text filters.
- Added Attendance navigation with branch, section, semester, Active/Warning/Inactive filters, summary counts, and visual distribution bars.
- Attendance status is computed from recorded sessions: Active >75%; Warning 65% through 75%; Inactive <65%.
- Students with no attendance rows display no percentage/status rather than a fabricated 0%.
- Switched the sidebar to a light theme to match the requested reference.
- Existing Student Performance and Marks Entry sections remain in place.

## Database migration required for Attendance
The current schema did not contain an attendance table. Apply `backend/migrations/001_create_attendance_records.sql` to the configured MySQL database before using the Attendance page.

The migration expects the existing `student(student_id)` table. Each row is one student/date and is either `PRESENT` or `ABSENT`; duplicate records for a student on the same date are prevented. The attendance endpoint calculates the percentage as present sessions divided by recorded sessions.

## CGPA
The existing student endpoint/schema does not expose a verified CGPA field or an agreed GPA conversion policy. The Students directory therefore displays `—` for CGPA rather than inventing a value. Once the university grading-to-GPA rule is confirmed, CGPA can be calculated from stored subject results.

## Charts and test status
The new attendance charts are lightweight frontend bar/distribution visualizations. The project already lists NumPy, Pandas and Matplotlib in `backend/requirements.txt`, but these new attendance visualizations are not yet generated by Matplotlib. Python syntax and JavaScript syntax checks passed in the packaging environment. The automated test suite could not be run in that environment because Flask/Werkzeug are not installed there; rerun the project's tests in its existing `.venv` after copying the files.
